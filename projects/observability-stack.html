Observability as Code — Prometheus + Grafana Stack

A full Observability as Code platform — Prometheus, Grafana, and AlertManager deployed and versioned via GitOps, with SLI/SLO definitions for critical IoT energy services.

The Challenge

Visibility without ClickOps — observable by default

Running a platform serving IoT-connected energy devices across Europe means incidents have real-world consequences — not just degraded UX. The team needed a monitoring stack that was itself treated as code: versioned, reviewable, and deployed through the same GitOps pipeline as everything else.

The goal was Observability as Code: no manually-configured Grafana dashboards, no hand-edited Prometheus rules, no alert configs only one person understood. Everything declarative. Everything in Git.

Implementation

Stack deployed via Helm + ArgoCD

The kube-prometheus-stack Helm chart is deployed via ArgoCD — including Prometheus Operator, Alertmanager, and the Grafana instance. All Grafana dashboards are provisioned as ConfigMaps from Git. All alert rules are defined as PrometheusRule CRDs. Nothing is configured in the UI.

SLI/SLO definitions are authored as recording rules — error budget burn rates trigger tiered alerting (page immediately vs. ticket for next sprint). On-call runbooks are linked directly inside alert annotations.

SOP — Adding a new alert rule
1
Author PrometheusRule CRD in Git
Create a new PrometheusRule manifest in the monitoring/rules/ directory. Define the expr, labels, and annotations including a runbook_url pointing to the team runbook.
apiVersion: monitoring.coreos.com/v1 kind: PrometheusRule metadata: name: energy-service-slo namespace: monitoring spec: groups: - name: slo.energy-service rules: - alert: EnergyServiceErrorBudgetBurn expr: | sum(rate(http_requests_total{job="energy-svc",status=~"5.."}[5m])) / sum(rate(http_requests_total{job="energy-svc"}[5m])) > 0.01 for: 10m labels: severity: page annotations: runbook_url: https://wiki.internal/runbooks/energy-service
2
PR + CI validation
GitHub Actions runs promtool check rules against all PrometheusRule files. Syntax errors fail the PR before review.
promtool check rules monitoring/rules/*.yaml
3
Merge → ArgoCD syncs → Prometheus picks up rule
ArgoCD detects the new CRD, applies it to the cluster. Prometheus Operator reconciles within 30s. No restart required.
