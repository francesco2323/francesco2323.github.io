Project Scope

A production-grade architecture designed from first principles

The capstone challenge: design and implement a multi-tier web application architecture on AWS that would be production-ready — highly available across two AZs, auto-scaling under load, secure by default, and cost-optimised for real business constraints.

The constraint that made it interesting: every decision had to be justified against the AWS Well-Architected Framework. Not just "it works" — but why this service over the alternative, what the failure modes are, and how the architecture recovers from them automatically.

Architecture Layers

Multi-tier design — every layer has a purpose

DNS + CDN
Route53 + CloudFront
Health-check-based DNS failover. CloudFront distributes static assets globally — reduces origin load and latency for EU users.
Load Balancing
Application Load Balancer
ALB in public subnets across 2 AZs. Path-based routing separates API traffic from frontend. Health checks gate all ASG instances before registration.
Compute
EC2 Auto Scaling Group
ASG in private subnets. Scales on CPU and custom CloudWatch metrics. Launch template with user data for bootstrapping. Min 2 / Max 6 instances.
Data
RDS Multi-AZ (PostgreSQL)
Primary in AZ-a, standby in AZ-b. Automatic failover in <60s. Encrypted at rest with KMS. No public accessibility. Security group allows only app tier.
Storage
S3 + Lifecycle Policies
Static assets and backups. Versioning enabled. Lifecycle rules transition objects to Glacier after 90 days. Bucket policy blocks all public access.

Implementation

Full Terraform implementation — not a click-through

Key Terraform modules authored
1
VPC + Networking
Custom VPC with public/private/database subnet tiers across 2 AZs. NAT Gateways for private subnet egress. VPC Flow Logs to S3 for security analysis.
module "vpc" { source = "terraform-aws-modules/vpc/aws" cidr = "10.0.0.0/16" azs = ["eu-central-1a", "eu-central-1b"] private_subnets = ["10.0.1.0/24", "10.0.2.0/24"] public_subnets = ["10.0.101.0/24", "10.0.102.0/24"] database_subnets = ["10.0.201.0/24", "10.0.202.0/24"] enable_nat_gateway = true single_nat_gateway = false # HA: one per AZ }
2
RDS Multi-AZ with automated failover
PostgreSQL RDS instance in Multi-AZ mode. Automated backups with 7-day retention. Parameter group tuned for application workload. Deletion protection enabled.
resource "aws_db_instance" "main" { engine = "postgres" engine_version = "15.3" instance_class = "db.t3.medium" multi_az = true storage_encrypted = true deletion_protection = true backup_retention_period = 7 db_subnet_group_name = aws_db_subnet_group.main.name vpc_security_group_ids = [aws_security_group.rds.id] }
3
Auto Scaling Group with CloudWatch scaling policies
ASG with launch template, target tracking scaling on CPU utilisation. Scale-in protection during deployments. Instance refresh for zero-downtime AMI updates.
4
DR and failover testing
Documented and executed: AZ failure simulation (terminate all instances in one AZ), RDS failover test, ASG replacement under load. All scenarios recovered automatically within defined RTOs.
