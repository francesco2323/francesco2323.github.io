AWS FinOps — Cloud Cost Governance Platform

From mysterious monthly AWS bill to per-team cost accountability — a FinOps implementation establishing tagging governance, Grafana cost dashboards, and rightsizing discipline.

AWS Cost ExplorerGrafanaTerraformAWS BudgetsIAM TaggingReserved Instances

The Challenge

Cloud spend was growing — without visibility or accountability

As Sonnen scaled on AWS, cloud spend grew fast. The problem was not the spend itself — it was the lack of visibility. Teams could not see what they were spending, management could not attribute costs to products, and there was no mechanism to detect or respond to cost anomalies.

The goal: establish a FinOps culture — turn cloud spend from a shared mystery into a managed, attributed, and optimised business asset.

Implementation

Three layers of cost governance

Layer 1 — Tagging governance via Terraform: All resources created via Terraform enforce a mandatory tag set: Environment, Team, Service, CostCenter. AWS Config rules alert on untagged resources. Tag compliance is automated, not manual.

Layer 2 — Grafana cost dashboards: AWS Cost Explorer data surfaced in Grafana via the AWS datasource plugin. Dashboards show spend per team, per environment, per service — with week-over-week trend lines and anomaly detection.

Layer 3 — Rightsizing + commitment analysis: Monthly review of AWS Compute Optimizer recommendations. Reserved Instance planning for stable baseline workloads. Spot instances for batch and non-critical workloads.

SOP — Monthly FinOps Review
1
Check AWS Config — tagging compliance
Run AWS Config rule evaluation to identify untagged or mis-tagged resources. Any non-compliant resource is filed as a ticket to the owning team.
aws configservice get-compliance-details-by-config-rule \ --config-rule-name required-tags \ --compliance-types NON_COMPLIANT
2
Review Grafana cost dashboards — anomaly detection
Check week-over-week spend per team. Any team with >20% spend increase vs prior week is reviewed. Common causes: forgotten dev environments, misconfigured autoscaling, data transfer spikes.
3
Compute Optimizer — rightsizing analysis
Review Compute Optimizer recommendations for EC2, EKS node groups, and RDS. Apply rightsizing recommendations for resources with consistent under-utilisation (<30% CPU/memory for 14 days).
aws compute-optimizer get-ec2-instance-recommendations \ --filters name=Finding,values=Overprovisioned
4
Reserved Instance / Savings Plan review
Quarterly: analyse on-demand spend for stable baseline workloads. Purchase 1-year Savings Plans for predictable compute. Target: 70%+ coverage of baseline spend via commitments.

Outcomes

What this delivered

Per-team cost accountability

Idle resource spend eliminated

Management visibility

100% resource tagging
