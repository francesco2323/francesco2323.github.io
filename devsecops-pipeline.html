DevSecOps Pipeline — Security as Default

Security and quality embedded directly into the GitHub Actions CI pipeline — TFLint and Trivy gate every change before Terraform plan runs, CODEOWNERS enforces review, and a self-hosted Renovate bot keeps dependencies current. Security and quality are the default, not an afterthought.

The Challenge

Security that scales without a dedicated security team

In a platform engineering team supporting multiple product teams, security reviews cannot be a bottleneck. The goal was to make it structurally impossible to deploy a workload with critical CVEs, overly permissive IAM, or non-compliant Kubernetes configurations — without adding a security gate that slows delivery.

The approach: shift security left and automate it into the pipeline. If the pipeline is green, the security bar has been met. No separate security review required for standard changes.

The CI Flow

Branch → PR → checks → plan → merge → deploy

Every change — application or infrastructure — starts on a new branch and goes through a Pull Request. The PR cannot merge until the GitHub Actions checks pass and a CODEOWNERS-listed reviewer approves. Only then does it merge to main, and the author deploys their own change.

CI pipeline — gates on every Pull Request
1
Open a PR from a feature branch
Work happens on a branch, never directly on main. The PR needs a clear title and description, relevant tests, and — per the development workflow — at least one review from a person listed in the repo's CODEOWNERS file.
git checkout -b feat/add-network-policy # make changes git push origin feat/add-network-policy # open PR -> CODEOWNERS auto-requested for review
2
TFLint runs — Terraform best-practice linting
For infrastructure changes, TFLint checks the Terraform for errors, deprecated syntax, and provider-specific best practices before anything is planned. A lint failure blocks the PR.
tflint --recursive
3
Trivy scans — vulnerabilities & misconfigurations
Trivy scans container images and IaC for known CVEs and misconfigurations. This is the security gate: findings above the threshold fail the check and the PR cannot proceed.
trivy fs --scanners vuln,misconfig . trivy image $ECR_REGISTRY/$IMAGE:$SHA
4
Only on success → Terraform plan
If — and only if — TFLint and Trivy pass, the pipeline runs terraform plan. The plan output is attached to the PR so the reviewer can see exactly what will change before approving. Nothing is applied at this stage.
terraform plan -out=plan.tfplan # plan output posted to the PR for review
5
CODEOWNERS review → merge → deploy
A CODEOWNERS reviewer approves, the PR merges to main, and the CI/CD pipeline applies the change and deploys. The PR author owns the deploy and monitors it through the platform's observability tools.

Keeping Dependencies Current

Self-hosted Renovate bot

A self-hosted Renovate bot runs as a GitHub Action on a schedule (hourly), scanning every repo it has access to and opening PRs for outdated dependencies. It groups updates into non-major and major batches, assigns reviewers from CODEOWNERS, and labels everything dependencies — so dependency hygiene is continuous and automated, not a quarterly scramble.

Renovate — central config
·
renovate.json — grouped, owner-assigned updates
{ "assigneesFromCodeOwners": true, "baseBranches": ["main", "dev"], "labels": ["dependencies"], "packageRules": [ { "groupName": "all non-major dependencies", "matchUpdateTypes": ["minor", "patch"] }, { "groupName": "all major dependencies", "matchUpdateTypes": ["major"] } ] }
First run on a repo opens an onboarding PR. Merge it and Renovate starts proposing dependency updates as reviewable PRs — each one going through the same TFLint + Trivy gates as any other change.

Outcomes

What this delivered

Vulnerabilities caught pre-merge
Trivy gates the PR. A change with findings above threshold cannot merge, so issues are fixed before they ship.
Review enforced by CODEOWNERS
No change reaches main without a code-owner approval and a green pipeline. The Git history is the audit trail.
Dependencies stay current
Self-hosted Renovate opens grouped update PRs hourly, auto-assigned to code owners — no stale, vulnerable dependencies.
Quality without slowdown
TFLint + Trivy run automatically on every PR. Plan only runs if they pass — fast feedback, no manual security review for standard changes.
